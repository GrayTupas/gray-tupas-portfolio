the problem

The plan lived in meetings, not on paper.

The requirements came out of client meetings, not a written spec. An AI coding agent will build whatever it's told, including features nobody has decided on yet. I needed a way to turn each meeting into a small, checked piece of work.

the result

What the client got.

A multi-page website, live since October 2026. A few days after launch it was the first source Google's AI answer pointed to for "document courier singapore".

Built so far

  • Home, quote and booking, corporate accounts, 5 service pages, contact, privacy, terms and cookies.
  • A table that matches what the customer needs to the right service.
  • Real Google reviews, a client logo wall, a story timeline and an FAQ.
  • A WhatsApp chat link and a sticky Call / Schedule a Pickup bar on phones.

Still in development

  • Booking calendar with a weekly cap the server enforces (Monday to Sunday, Singapore time).
  • Tracking link in order emails.
  • Reminder email.
  • "Track a delivery" link.

how I did it

Every change took the same path.

I designed and built the whole site myself, with Claude Code as my coding agent. I wrote every prompt, reviewed every build, and decided what was ready to go in.

  1. Client meetingThe client says what they want and reacts to the current version.
  2. TranscriptThe meeting transcript is the source for the next piece of work.
  3. One scoped promptOne prompt per piece of work, with checkpoints written into it.
  4. BuildThe agent builds up to the next checkpoint, then stops.
  5. ReviewI check the result before the next step starts.
  • Scope from the meeting. Each prompt was written from a meeting transcript, so the work matched what the client actually asked for.
  • Hold back what isn't ready. Features still in development stay listed as in development, never presented as finished.
  • Checkpoints in every prompt. The agent stops at set points so I can review before it continues.
  • Rules and history live in files. One file holds the build rules and a decision log keeps the history, so nothing depends on memory.
